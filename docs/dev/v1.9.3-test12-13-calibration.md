## §1 工作包（WP）

### WP1 · source 格式全链路统一为 object（P1）

**根因**：v1.5 WP3 定档「统一 source schema（object）」时，只改了 schema 与 import 转换，未同步 ingest 模板、12 个笔记模板与 v0.2/v0.3 规范示例——「引入-漏同步」第 4 例（前 3 例见 v1.9.2 CHANGELOG）。capture 的 inbox source（嵌套字典）本来就是 object，进一步确认 object 为正确方向。

**改动**：

1. `skills/quick-kb-ingest/SKILL.md` §2.5 模板：list → object + 「禁 list 格式」注释
2. 模板 12 文件：`templates/{zh,en}/` 与 `skills/quick-kb-init/templates/{zh,en}/` 两套副本 × note-concept / note-resource / experience
3. 规范：`references/frontmatter-v0.2.md` §2 字段表（`list of {url?, note?}` → object 键集）+ §6 示例；`references/frontmatter-v0.3.md` §2 字段表 + §6/§7 两处示例
4. 文档：`docs/DESIGN.md` 两处、`docs/SKILLS_SPEC.md` 两处（inbox 与入库示例各一）
5. schema：`frontmatter-schema-v1.json` source properties 补 `capture_type`（v1.5 WP7 要求 ingest 保留溯源键但 schema 一直未收录）/ `author` / `published`（resource 模板既有键）

**BREAKING 说明**：v1.9.3 前按旧模板产出的 list 格式 source 为不合规；存量由 WP2 迁移，不要求用户手工改。

### WP2 · normalize source 迁移能力（P1）

1. schema_check 检查项 #6 扩展：「source 为 list 格式」列为违规（v1.9.3 起），失败示例补充两类来源
2. run 步骤 2.1 新增 **source list → object 迁移**：各 list 项键值对平铺进同一 source 字典；键冲突保留首个 + `needs_review: true`；写 diff log「source list → object」；已为 object 或缺失 → 幂等不动
3. 自检清单补幂等项

### WP3 · init 顶层目录负向断言（P2，漂移防御）

**根因**：同类执行漂移已连续三轮出现（测试10「03/04 倒置」、测试12「自创 08/09/10」），而 init 自检只有正向断言（目录齐全），无「不得多余」约束。

**改动**：init 自检清单新增——vault 根目录集合须与骨架**精确匹配**（10 个顶层目录 + `_normalize_log/` + 用户文件），出现自创目录 → ⚠⚠ 报告「结构漂移」并建议删除/迁移，不得静默保留。

### WP4 · ingest 写入前近似重复检查（P3）

ingest 新增 §2.4b：落盘前对目标目录既有笔记做标题近似检查（slug 词集 Jaccard > 0.8 或单复数/连字符变体）→ 命中提示三选一（并入既有 / 新建+evolves / 确认新建），**不自动合并**。与 §2.7 关系推荐共用 manager-agent 相似度契约（scoring.md §5 阈值口径）。

### WP5 · detect_orphans 排除 MOC（P3）

排除 `type: moc` 与 init 铺设的 `_moc.md` 空占位；单列「未填充 MOC 占位 N 个」提示运行 connect 补充，不计入孤立清单。

### WP6 · import 跨语言弱键（P3）

dedupe 弱键条件 C：中文标题与既有英文 slug 核心域名词根重叠（如「向量数据库选型标准」vs `vector-database-selection-criteria`）→ ⚠ 疑似重复标注，不改变导入行为。

### 收尾

17 个 SKILL.md `version` 统一 → v1.9.3；CHANGELOG v1.9.3 条目（含拒绝修复清单）。

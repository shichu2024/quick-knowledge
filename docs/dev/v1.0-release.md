# v1.0 · 发布开发文档

> 代号 **release** · 对外发布到 GitHub + skills marketplace。无新功能，全是发布打磨。

---

## 1. 目标

让 quick-knowledge：
- 公开仓库可被克隆使用
- 文档完备，新用户能自助上手
- 通过基础 CI 检查
- 可一键安装到主流 runtime（Claude Code / Codex / Cursor / OpenCode 等）
- 发布到 skills marketplace

**用户体验跃迁**：从"作者自用"到"社区可用"。

---

## 2. 范围

### In Scope

- 完善主 README（中英双语已在 v0.4，本阶段做最终打磨 + 效果示例）
- 完善用户文档（快速开始已在 v0.4，本阶段加进阶指南）
- demo-vault 完善（覆盖 v0.1-v0.4 全部能力）
- `CONTRIBUTING.md` / `COMMUNITY.md` / `CODE_OF_CONDUCT.md`
- `LICENSE`（MIT）
- CI 基础检查（frontmatter 校验、链接检查、demo-vault 可运行）
- `.github/` 模板（issue / PR 模板）
- `.claude-plugin/marketplace.json` + `plugin.json`（对齐 obsidian-skills 模式）
- 发布材料（介绍文 / 截图 / 录屏）

### Out of Scope

本阶段不引入新功能。所有功能性变更应在 v0.1-v0.4 完成。如发现 v1.0 前必修的 bug，按补丁处理（不升主版本）。

## 4. 工作包详述

### WP1 · README 最终打磨

**交付**：参考 nuwa-skill 的 README 结构，最终版含：
- Hero 区（项目定位一句话 + badge：License / Agent Skills / skills.sh / Multi-Runtime）
- 效果示例（2-3 个真实对话/操作场景，展示 advisor / memory / Decision Ledger 的差异化）
- 安装（npx skills / 手动按 runtime / 参考）
- 使用（典型场景）
- 工作原理（六大闭环 + 三 agent + 主动提醒）
- 仓库结构
- 多语言切换栏
- 关于作者 / 许可证

- **依赖**：v0.4 完成
- **验收**：README 自包含、新用户读完能安装使用

### WP2 · 用户文档体系

**交付**：
- `docs/quick-start.md`（v0.4 基础，本阶段打磨）

- **依赖**：v0.4 完成
- **验收**：覆盖所有用户可达功能

### WP3 · demo-vault 完善

**交付**：`examples/demo-vault/` 覆盖 v0.1-v0.4 全部能力：
- 完整目录骨架
- 各 type 笔记样例（concept/resource/principle/belief/pattern/experience/decision/goal/project/moc）
- 至少 1 条含 `contradicts` 的冲突对照
- 至少 1 条 Decision Ledger（含 expected/actual/lesson 完整闭环）
- 一条 experience 是从某 decision 的 lesson 派生而来（演示 v0.3 派生）
- 一份 review 周报样例
- `_readme.md` 引导浏览顺序

- **依赖**：v0.4 完成

## 7. 风险与降级

| 风险 | 应对 |
|------|------|
| CI 在 Windows/macOS/Linux 表现不一致 | 主要在 Linux 验证；其他平台标"社区支持" |
| skills.sh / marketplace 协议变化 | 跟随 obsidian-skills / nuwa-skill 最新实践 |
| 录屏环境难复现 | 录屏脚本化，使用 demo-vault 标准化输入 |
| 文档量大维护成本 | 用户文档与设计文档单一来源（相互引用，不复制） |

## 9. 发布后维护

v1.0 发布后进入维护期：
- bug 修复：补丁版本（不升主版本）
- 新技能 / 新模板：可作为社区贡献，按 COMMUNITY.md 索引
- 重大设计变更：先在设计文档升版本（V3/V4...），再开发对应阶段（v1.1/v2.0...）

发布不是终点，而是社区演进的起点。

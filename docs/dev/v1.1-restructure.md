# v1.1 迁移指南 · 目录流转制 + 路径硬约束

> 发布日期：2026-08-09 · codename `flow-restructure` · ⚠️ 含 BREAKING CHANGE

本指南帮助 v1.0 vault 用户手动迁移到 v1.1。背景决策见 `docs/DESIGN.md` ADR-015。

---

## TL;DR

两件事变了：

1. **vault 顶层目录加 `NN_` 数字前缀**（按「输入 → 沉淀 → 目标 → 执行 → 产出 → 索引 → 系统」流转语义排序）
2. **文档引用禁止绝对路径**（外部依赖必须复制到 `01_resources/`）

---

## 1. 目录重命名映射

| v1.0 | v1.1 |
|------|------|
| `inbox/` | `00_inbox/` |
| `resources/` | `01_resources/` |
| `areas/` | `02_areas/` |
| `goals/` | `03_goals/` |
| `projects/` | `04_projects/` |
| `outputs/` | `05_outputs/` |
| `wiki/` | `06_wiki/` |
| `principles/` | `07_principles/` |
| `archive/` | `98_archive/` |
| `system/` | `99_system/` |

### 1.1 物理重命名（git mv 优先，保留历史）

```bash
cd <your-vault>
git mv inbox    00_inbox
git mv resources 01_resources
git mv areas    02_areas
git mv goals    03_goals
git mv projects 04_projects
git mv outputs  05_outputs
git mv wiki     06_wiki
git mv principles 07_principles
git mv archive  98_archive    # 若存在
git mv system   99_system
```

> Windows 大小写敏感问题：必要时两步重命名（`inbox` → `_tmp_inbox` → `00_inbox`）。

### 1.2 wikilink 重写（仅完整顶层路径）

笔记内 `[[areas/foo]]` / `[[projects/bar]]` 等完整顶层路径 wikilink 需要同步加前缀：

```bash
find . -name "*.md" -type f -print0 | xargs -0 sed -i -E '
  s|\[\[principles/|[[07_principles/|g;
  s|\[\[inbox/|[[00_inbox/|g;
  s|\[\[resources/|[[01_resources/|g;
  s|\[\[areas/|[[02_areas/|g;
  s|\[\[goals/|[[03_goals/|g;
  s|\[\[projects/|[[04_projects/|g;
  s|\[\[outputs/|[[05_outputs/|g;
  s|\[\[wiki/|[[06_wiki/|g;
'
```

### 1.3 不要碰这些（白名单）

- `status: inbox` / `status: archived`（frontmatter 枚举值，**不是路径**）
- `[[principle/xxx]]` / `[[belief/xxx]]` / `[[pattern/xxx]]` / `[[experience/xxx]]`（省略前缀形式，`check-links.mjs` 用 basename 兜底解析）
- 任何非 wikilink 上下文里的英文单词（如 `[[quick-kb-archive]]` skill 名）

### 1.4 验证

```bash
node <repo>/scripts/check-frontmatter.mjs <vault>/
node <repo>/scripts/check-links.mjs <vault>/
# 期望：两者皆 0 failures
```

## 2. 路径硬约束（任务 A）

### 2.1 规则

- **禁止绝对路径**：`source.url`、`source.raw`、笔记内联引用不得使用 `file://`、`C:\`、`/Users/...` 等绝对路径
- **外部依赖复制入库**：本地外部文件先复制到 `01_resources/` 下相应子目录，再以 vault 相对路径引用
- **source.url 合法形态**：仅 `https://原始来源 URL` 或 `01_resources/...` 相对路径

### 2.2 自查

```bash
# 扫描 vault 内所有 source.url 绝对路径违规
grep -rnE "^(source\.url|source_url|source:[[:space:]]*$)" <vault>/ --include="*.md" -A 1 \
  | grep -E "(file:|[A-Za-z]:[\\/])"
```

CI 已内置此校验（`check-frontmatter.mjs` v1.1+），本地可单跑。

### 2.3 现存违规修复

若 v1.0 vault 里有 `source.url: file:///E:/...` 这种：

1. 把外部文件复制到 `01_resources/<subdir>/`
2. 改 `source.url: 01_resources/<subdir>/<file>`
3. 删除原外部路径引用

## 3. `.kb-initialized` 字段

v1.1 起 init 会在 `.kb-initialized` 加 `restructured_at` 字段：

```
quick-knowledge vault
version: v0.1
initialized_at: 2026-08-07T09:00
restructured_at: 2026-08-09 (v1.1)   # ← v1.1 新增
language: zh
...
```

`version: v0.1` 保留不变（这是 frontmatter schema 版本，不是 plugin 版本）。

---

## 4. 不提供自动迁移脚本的理由

- vault 千差万别，自动 sed 易误伤用户自定义内容
- 迁移表只有 10 条，手动成本低于写「安全的自动迁移」成本
- BREAKING 已在 CHANGELOG 与本文件充分告知

社区若贡献自动迁移脚本，欢迎提 PR。

# v0.3 · 个人助手开发文档

> 代号 **assistant** · 从「带引用的 RAG」升级为「个人决策助手」。这是 quick-knowledge 区别于通用 Wiki 工具的核心差异化阶段。

---

## 1. 目标

让库能：
- 调取**个人历史经验**辅助决策（memory-agent + advisor）
- 管理**个人认知资产**（principles / beliefs / patterns / experiences）
- 跟踪**知识成熟度**（maturity 6 态 + Knowledge Score）
- 用 Decision Ledger 形成 **决策→结果→教训** 闭环
- 在关键事件**主动提醒**（全量 7 类事件）

**用户体验跃迁**：从"我搜得到"到"AI 主动基于我的经验帮我决策"。

## 4. 工作包详述

### WP1 · maturity + Knowledge Score

**交付**：
- 在 frontmatter 加入 `maturity`（仅知识型笔记：concept/principle/belief/pattern/experience）
- Knowledge Score 公式：`KS = confidence × log2(1 + reuse) × impact`
- manager-agent 在 review 时计算 KS 并排序

**关键点**：
- maturity 6 态：captured → understood → validated → applied → teachable → deprecated
- deprecated 必须关联 `supersedes`/`contradicts`（ADR-011）
- KS 不写入笔记，仅 review 时排序用

- **依赖**：v0.2 完成
- **验收**：知识型笔记含 maturity；review 输出"高价值低置信"优先级清单

### WP2 · 认知资产（principles/ + 4 类 type）

**交付**：
- 新建 `principles/{principles,beliefs,patterns,experiences}/` 根目录
- type 枚举加 `principle`/`belief`/`pattern`/`experience`
- 4 类中英双语模板
- 这 4 类**无 `domain`**（横切），但允许领域目录覆盖（如 `areas/front-end/principles.md`）

**关键点**：这是个人 KB 与通用 Wiki 的本质区别（ADR-007）。

- **依赖**：v0.2 完成
- **验收**：能创建 4 类笔记并写入对应目录

### WP3 · memory-agent（核心）

**交付**：`agents/quick-kb-memory-agent.md`，完整实现 AGENTS_SPEC §3。

**关键实现点**：
- 能力：`recall_similar` / `check_beliefs` / `detect_repeat_mistakes` / `proactive_suggest` / `present_conflicts`
- **召回排序公式**（必须严格按规格）：
  ```
  score = similarity^0.45 × recency_factor^0.20 × impact_factor^0.15 × confidence_factor^0.20
  ```
- **类型加权**：experience ×1.5（失败再 ×1.2）、pattern ×1.3、decision ×1.2、principle ×1.1、belief ×0.9、concept ×1.0、resource ×0.7
- **冲突呈现规则**（§3.6）：含 `contradicts` 时双方同时返回 + 各自 context，不选边
- **降级**：库 < 50 条返回"经验不足"；无 embedding 降为标签 Jaccard

- **依赖**：WP1、WP2（要有认知资产可调）
- **验收**：
  - 输入情境 → 召回相似经验/失败案例，排序合理
  - 召回含 contradicts → 双方同时呈现
  - 库 < 50 → 降级提示

### WP4 · quick-kb-advisor 技能

**交付**：实现 SKILLS_SPEC §6 完整工作流。

**关键点**：
- 调用 memory-agent（`recall_similar` + `check_beliefs`）
- 输出三段：你的历史 / 你的原则 / 建议路径
- 候选方案与某条 experience 教训冲突时显式警告
- 缺口提示（建议 capture 本次决策）

- **依赖**：WP3
- **验收**：用户描述决策情境 → 输出含历史经验引用的建议

### WP5 · quick-kb-project 技能（含 Decision Ledger）

**交付**：实现 SKILLS_SPEC §10 完整工作流。

**关键点**：
- init：调 memory-agent 主动召回相似项目 → README 顶部生成"经验复用建议"段
- init：引导生成首条 Decision Ledger（含 expected，留 actual/lesson 待归档）
- **archive 闭环**（V2 关键）：
  1. 扫描本项目 `decisions/`
  2. 补全每条 Decision Ledger 的 `actual` 与 `lesson`
  3. **每条 lesson 自动派生为独立 `experience` 笔记**到 `principles/experiences/`
  4. 在原 decision 建立 wikilink 指向派生的 experience
- 归档复盘含 expected vs actual 偏差分析

- **依赖**：WP2、WP3、Decision Ledger 模板（WP7）
- **验收**：
  - 新建项目 → memory 提示相似项目
  - 归档项目 → lesson 派生 experience 笔记可被后续 advisor 召回

### WP6 · quick-kb-goal 技能

**交付**：实现 SKILLS_SPEC §9 完整工作流。

**关键点**：
- create：调 research-agent 生成学习路径（库内已有笔记优先关联）
- progress：追加进展 + 里程碑勾选 + 路径动态调整
- complete/cancel：归档 + 状态传播（相关笔记 status/maturity 视情况调整）

- **依赖**：v0.2 的 research-agent
- **验收**：新建目标 → 学习路径；更新进度 → 里程碑更新；完成 → 归档

### WP7 · Decision Ledger 模板（中英双语）

**交付**：`templates/{zh,en}/decision.md`，含完整 8 字段闭环：
`problem / options / chosen / reason / rejected / expected / actual / lesson`

- **依赖**：WP2（type=decision 已在 v0.1 就有，本阶段强化模板）
- **验收**：模板字段完整；lesson 字段在 project archive 时被提取为 experience

### WP8 · 冲突呈现规则落地

**交付**：在 query / advisor / memory-agent 召回含 `contradicts` 时，统一执行：
1. 双方同时呈现
2. 各自 `context` 显式标注
3. `reasoning` 中说明情境对照
4. 缺口提示（如当前情境与双方都不完全匹配，建议 Capture 决策跟踪 actual）

- **依赖**：WP3、v0.2 的 query
- **验收**：召回冲突笔记时，输出符合 AGENTS_SPEC §3.6 的格式

### WP9 · 主动提醒机制全量

**交付**：在 v0.2 的 manager 事件基础上，补齐 memory 事件，实现 DESIGN §7.6 全部 7 类：

| 事件 | 触发 agent | 阶段 |
|------|----------|------|
| 新建项目 | memory | v0.3 新增 |
| 新建目标 | memory | v0.3 新增 |
| Capture 某主题素材 | memory | v0.3 新增 |
| Ingest 新笔记 | manager | v0.2 已做 |
| Ingest 检测冲突 | memory | v0.3 新增 |
| Review 完成 | manager | v0.2 已做 |
| 长期未触碰 applied 笔记 | manager | v0.3 新增 |

**限流**：单次 ≤ 3、去重、库 < 50 关闭、可在 config 关闭某类（详见 AGENTS_SPEC 附录）。

- **依赖**：WP3、WP5、WP6
- **验收**：7 类事件各跑一遍，提醒合理且不超限

### WP10 · manager-agent 扩展

**交付**：在 v0.2 manager 基础上加：
- `detect_structure_drift`：子领域增速异常 → 升格建议
- KS 排序（接 WP1）

- **依赖**：WP1
- **验收**：某子领域 ≥ 30 条时 review 输出升格建议

## 7. 风险与降级

| 风险 | 应对 |
|------|------|
| memory-agent 召回不准（无 embedding） | 降级标签 Jaccard；明确告诉用户"经验召回基于规则" |
| 决策 lesson 自动派生质量低 | 派生时标 `status: draft`，由用户确认 |
| maturity 字段用户填不准 | AI 在 review/ingest 时基于 confidence + 触碰记录建议 maturity |
| 主动提醒变噪音 | 严格限流；用户可关闭某类 |
| 项目归档时 actual/lesson 缺失 | 提示用户补全；缺失则 lesson 字段为空，不强行派生 |

## 9. 阶段里程碑意义

v0.3 完成后，quick-knowledge 真正具备「个人 AI 助手」形态：
- 不只是回答"是什么"（query），更能基于个人经验建议"怎么做"（advisor）
- 不只是积累笔记，更能形成「决策 → 结果 → 教训 → 复用」闭环（Decision Ledger + experience 派生）
- 不只是被动响应，更能主动提醒（7 类事件）

后续 v0.4 是工程化扩展，v1.0 是发布打磨，不再有结构性新概念。

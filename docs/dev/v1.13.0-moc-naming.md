# v1.13.0 · MOC 命名统一与位置收敛

日期：2026-08-21
起因：用户报告「每个目录都会生成 `_moc`」+「_moc 全部同名不好展示」。排查 E:\knowledge 真实 vault 后校准问题定义。

## §0 校准（问题重定义）

初判「`03_goals/daily-learning/_moc.md` 是执行漂移」**方向错误**——goal SKILL 自己规定了「目标内索引 `_moc.md`」+「更新顶层 _moc.md」（步骤 3/7、progress 步骤 6、complete 步骤 5、自检清单），project SKILL 同样规定「项目内索引 `_moc.md`」（真相源 SKILLS_SPEC §10 第 4 步）。真实矛盾是**规格内冲突**：

- init/ingest/DESIGN 口径：领域 MOC 只在 `02_areas/<domain>/`
- goal/project SKILLSPEC 口径：03_goals/04_projects 内也建 `_moc.md` 索引

两套口径共存导致 MOC 概念泛滥（每目录一个索引文件）且全库同名（Obsidian 图谱/快速切换/标签页全部显示 `_moc`，不可区分）。

## 4 项变更

### WP-A 方案 A：领域 MOC 改名 `<basename>-moc.md`

- `02_areas/<domain>/_moc.md` → `02_areas/<domain>/<basename>-moc.md`（basename=目录名；zh 库保留中文如 `编程-moc.md`；语言判定链同 write-validation-rules §6.1）
- 与既有主题 MOC `06_wiki/mocs/<domain>-moc.md` 命名统一——本质是把两套 MOC 命名合成一套
- 落点：init SKILL（骨架图/§3.4 内嵌 _index/§3.6/兜底澄清/报告示例/自检）+ ingest 降级表 + manager-agent（detect_orphans 排除、promote_to_domain 示例）+ DESIGN §4 骨架 + demo-vault（git mv 2 文件 + _index.md 链接）

### WP-B 优化 2：嵌套 domain 层级规则澄清

- init：对**每个用户显式输入的 domain**（含被显式列出的嵌套父层）建 MOC；嵌套展开产生的中间目录不自动建
- ingest：新建嵌套 domain 只建目标层
- 既有中间层 hub（如 `02_areas/编程/编程-moc.md`）合法——MOC 合法位置=02_areas/ 任意层级。规则与真实 vault 演化对齐

### WP-C 优化 1：goal/project 去索引化（规格修正核心）

- goal SKILL：删除 `_moc.md` 产物（create 步骤 3/7、progress 步骤 6、complete 步骤 5、自检）；「不做」段新增「不创建 MOC/索引占位——goal.md 是唯一索引入口」
- project SKILL：同口径删除（目录树/init 步骤 8/update 步骤 4/archive 步骤 7/输出示例）；「不做」段新增；偏差表补 v1.13.0 决策行
- SKILLS_SPEC §10：goal create 第 4 步、project init 第 4 步改为「不建立任何 MOC/索引占位」
- DESIGN §4：03_goals 骨架删 `_moc.md` 行
- **依据**：goal.md（学习路径+进度记录段）与 _readme.md（说明+进度索引）已各自承担索引入口职责，第二索引是冗余

### WP-D 优化 3：normalize 防线

- schema_check 新增检查 #11「MOC 位置与命名」：`type: moc` / `*-moc.md` / `_moc.md` 出现在 02_areas 与 06_wiki/mocs 之外 → ⚠「MOC 越界」结构漂移报告
- 新增 `action=migrate_moc`（幂等）：`02_areas/**/_moc.md` → `<basename>-moc.md` 重命名 + 全库 wikilink 同步改写（alias 保留）+ 冲突三态（占位删除 / 双正文 ⚠ 手动合并）+ diff log
- 存量 vault 升级路径：跑 `normalize action=migrate_moc`，再手动处理 03_goals/04_projects 下的越界 MOC（建议删除，入口文件已覆盖其功能）

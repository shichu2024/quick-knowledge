## §1 工作包（WP）

### WP1 · init 资源自包含与 schema 单一权威源（P0）

**根因**：init 的模板与 schema 均来自仓库级资源（`templates/`、`references/`），但技能目录自包含分发时这些资源不可达，兜底承诺（内嵌模板）不成立，导致执行 LLM 即兴生成第三套 schema / 占位模板，污染下游所有技能。

**改动**：

1. **技能自带资源**：在 `skills/quick-kb-init/` 下新增 `templates/zh/`、`templates/en/`（复制仓库根 `templates/`）与 `references/frontmatter-schema-v1.json`，使三级回退的第 ① 级真实命中。
2. **修正回退表措辞**：init SKILL.md §3.3 中第 ③ 级「SKILL 内联模板文本（与 templates/zh/ 字节级一致）」改为如实描述——仅 4 个系统文件内嵌，12 个笔记模板不内嵌；① ② 均未命中时写入占位模板并 ⚠ 高亮。
3. **schema 权威性标记**：init 复制 schema 到 vault 时，在 `.kb-initialized` 或升级报告中记录 schema 内容指纹（SHA-256 前 8 位）；upgrade 子流程校验指纹，不一致（用户手改或即兴版本）→ ⚠ 询问是否以权威版覆盖。
4. **即兴生成禁止条款**：init SKILL.md 增加「若 ①② 级均不可达，**禁止自行编写 schema 内容**，只能落盘占位声明文件 + ⚠ 提示用户设置 `QUICK_KB_REPO_ROOT` 或重装技能包」。
5. 同步检查 connect / ingest 等 SKILL.md 中对 `references/frontmatter-v0.2.md` 的相对链接语义（vault 内该文件不存在时应指向技能包内或仓库根）。

**涉及文件**：`skills/quick-kb-init/SKILL.md`、`skills/quick-kb-init/templates/**`（新增）、`skills/quick-kb-init/references/frontmatter-schema-v1.json`（新增）。

### WP2 · 写入前校验层（P0，ROI 最高）

**根因**：12 条误报 + 死链 53.6% 的共同根因。校验只存在于 normalize（事后），所有写入型技能落盘前无拦截。

**改动**：

1. **新增共享校验规则**：`references/write-validation-rules.md`，定义写入前最小校验集：
   - frontmatter：必填字段（title/type/created/updated/status）、`confidence` 为 0-100 整数、`relations` 为类型化 dict（键 ∈ schema enum）、`maturity` ∈ 6 态词表、禁止自创字段/自创关系类型（如 complements）
   - wikilink：`[[X]]` 目标必须已存在（vault 文件名索引内），否则降级为普通文本或加粗；禁止路径式与双前缀写法（对齐 `references/wikilink-conventions.md`）
2. **6 个写入型技能接入**：ingest / capture / connect / daily / goal / project / import 的 SKILL.md 各增加「写入前校验」步骤（位于写文件之前）：校验失败 → 按规则修正后写入，**不得静默落盘不合规内容**；降级（如无文件索引可查）时在输出中 ⚠ 标注。
3. **步骤级 checklist 强化**：connect 的双向写入（supports/evolves 反向键补全）与关系去重，在步骤描述中改为「写入后自检」子步骤（写 A→B 后必须检查 B 的 frontmatter 已含反向键）。

**涉及文件**：`references/write-validation-rules.md`（新增）、ingest / capture / connect / daily / goal / project / import 各 SKILL.md。

### WP3 · 跨技能口径统一（P1）

1. **import 目录命名**：统一为 `00_inbox/imported/<source>/`，修正 import SKILL.md 完成提示与 ingest 建议中的 `_imports/` 残留。
2. **缺失率口径**：review SKILL.md 的 frontmatter 缺失率步骤改为显式引用 stats §4.1 的必填字段集 + 相同扫描范围（跳过 `98_archive/`、`99_system/`）；stats/review 输出中注明口径版本。
3. **降级相似度权重定档**：`references/scoring.md` 增补「无 embedding 降级公式」小节，统一定为「标签 Jaccard × 0.6 + 标题关键词重叠 × 0.4」（或另行定档），manager-agent / memory-agent / query / advisor 的降级段统一引用该条目，不再各自写权重。
4. **manager-agent 措辞**：§3.6 `refresh_value` 标题与描述标注「写回型操作（非纯函数）」，与不变量段的例外说明一致。
5. **research-agent 不变量澄清**：不变量段补一句「`existing_notes` 由调用方传入（输入参数），research-agent 自身不主动读取库内笔记」。

**涉及文件**：import / review / stats / manager-agent / memory-agent / query / advisor / research-agent 各 SKILL.md、`references/scoring.md`。

### WP4 · archive 语义修正（P1）

消除「不派生 experience」与步骤 10 派生草稿的矛盾，二选一（推荐 a）：

- a. §2 能力表与首节改为：「通用归档不派生 experience；**仅当归档对象 type=project 时**，执行 lesson → experience 草稿半自动化（status: draft，需用户确认）」
- b. 删除步骤 10，project 类归档重定向到 quick-kb-project archive

**涉及文件**：`skills/quick-kb-archive/SKILL.md`。

### WP5 · 技能版本元数据同步（P2）

1. 17 个 SKILL.md frontmatter `version` 统一升为本次发布版本，消除 v0.1~v1.4 混杂。
2. `.kb-initialized` 的 `skill_version` 比较逻辑明确化：init SKILL.md 说明「以 17 技能统一版本号为准」，避免逐技能比较时新旧交错导致 upgrade 误判。

**涉及文件**：17 个 SKILL.md、`skills/quick-kb-init/SKILL.md`（upgrade 段）。

## §3 验收标准

1. **重新初始化测试**：在无 `QUICK_KB_REPO_ROOT`、技能目录自带资源的条件下运行 init，vault `99_system/config/frontmatter-schema.json` 与 `references/frontmatter-schema-v1.json` 字节级一致；模板文件非占位。
2. **写入校验生效**：构造 3 类违规输入（confidence 小数、自创关系类型、`[[不存在目标]]` wikilink）过 ingest/connect，输出应含修正记录或 ⚠，落盘内容合规。
3. **口径一致**：同一 vault 分别跑 stats 与 review，frontmatter 缺失率数值一致（同字段集 + 同扫描范围）。
4. **命名一致**：import SKILL.md 全文仅出现 `imported/` 一种目录名；完成提示给出的 ingest scope 路径真实存在。
5. **语义一致**：archive SKILL.md 内无「不派生 experience」与派生步骤并存；research-agent 不变量段与输入定义无矛盾表述。
6. **Bench 回归**：capture split=test 9/9 hard；flow split=train 在已知方差内（2-4/6 hard，soft ≥0.65）。

## §4 测试方法学改进（记入下次测试，非技能改动）

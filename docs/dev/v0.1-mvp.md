# v0.1 · MVP 开发文档

> **历史路径说明**：本文为 v0.x 形态，目录路径示例为扁平命名（`inbox/` / `areas/` 等）。v1.1 起顶层目录改为 `NN_` 前缀（`00_inbox/` / `02_areas/` 等），详见 `docs/DESIGN.md` ADR-015 与 `docs/dev/v1.1-restructure.md`。

> 代号 **mvp** · 跑通 Capture → Ingest 最小闭环，用户能立即开始记笔记。

---

## 1. 目标

让用户安装后：
1. 一行命令初始化空 vault
2. 快速采集灵感/网页到 inbox
3. 把 inbox 素材结构化入库到 areas/resources
4. 记每日日志，AI 反问补充细节

**最小可用标准**：用户从 0 到第 1 条正式笔记，不超过 3 步交互。

---

## 2. 范围

### In Scope

- 4 个核心技能：`init` / `capture` / `ingest`（简化版）/ `daily`
- 4 个中文模板：concept / idea / daily / resource
- 基础 frontmatter（不含 maturity / value / relations / context）
- demo-vault 示例（10-15 条笔记）

### Out of Scope（推迟）

| 推迟项 | 目标阶段 |
|--------|---------|
| connect / query / review 闭环 | v0.2 |
| 任何 agent | v0.2 |
| 完整 frontmatter（maturity / value / relations / context） | v0.2 |
| Obsidian-skills 集成 | v0.2 |
| 主动提醒机制 | v0.2 |
| 英文模板 | v0.2 |
| PDF / 会议 / AI 对话采集 | v0.2 |

## 4. 工作包详述

### WP1 · v0.1 frontmatter 子集规范

**交付**：`references/frontmatter-v0.1.md`，明确本阶段仅支持的字段。

```yaml
---
title:        # 必填
type:         # 必填 · v0.1 仅 concept/resource/idea/daily
created:      # 必填 · ISO date
updated:      # 必填 · ISO date
tags:         # 必填
status:       # 必填 · v0.1 仅 inbox/draft/active/done
source:       # 可选
domain:       # 可选
---
```

- **依赖**：无（关键路径）
- **关键点**：明确 v0.1 不写 `maturity`/`value`/`relations`/`context`，避免后续迁移
- **验收**：所有 v0.1 技能产出的笔记 frontmatter 仅含上述字段

### WP2 · quick-kb-init 技能

**交付**：实现 SKILLS_SPEC §1 完整工作流。

**关键点**：
- 创建 DESIGN §4 目录骨架（含 `.gitkeep`）
- 生成最小 `kb.config.yaml`（仅 `language: zh`）
- 铺设 4 个中文模板到 `system/templates/zh/`
- 写入 `.kb-initialized` 标记（版本号 + 日期）
- **幂等**：检测已初始化时提示而非覆盖

- **依赖**：WP1
- **验收**：空目录运行后，目录树与 DESIGN §4 一致（v0.1 范围内）；二次运行不破坏

### WP3 · quick-kb-capture 技能（简化）

**交付**：实现 SKILLS_SPEC §2 工作流的子集。

**支持源**：纯文本 / URL（PDF / 会议 / AI 对话推迟）
**最小 frontmatter**：`title` + `captured_at` + `suggested_tags`
**去重**：基于标题相似度（无 embedding）
**不做**：主动提醒（推迟 v0.2）

- **依赖**：WP1
- **关键点**：URL 抓取走基础 HTML→Markdown（无 defuddle，v0.2 集成）；保留原始正文到 `inbox/clips/_raw/`
- **验收**：
  - URL 输入 → 抓取干净正文 → 写入 `inbox/clips/`
  - 文本输入 → 写入 `inbox/ideas/`
  - 重复输入触发提示

### WP4 · quick-kb-ingest 技能（简化）

**交付**：实现 SKILLS_SPEC §3 工作流的基础部分。

**做**：
- 扫描 inbox 候选
- 抽取原子观点（一笔记一观点）
- 分类去向（concept → `areas/`，resource → `resources/`）
- 补全基础 frontmatter
- `source.note` 指回 inbox 原始素材
- 置信度初值规则（单源 40 / 多源 60+ / 一手 80+）

**不做**：
- 不调用 research-agent（v0.2 才上），用内置 LLM 直接抽取
- 不做关系类型化（`relations`）—— v0.2
- 不做冲突检测 —— v0.2

- **依赖**：WP1、WP3（要有 inbox 候选测试）
- **验收**：inbox 一条素材 → ingest 后产出 1-N 条 `areas`/`resources` 笔记，frontmatter 完整

### WP5 · quick-kb-daily 技能

**交付**：实现 SKILLS_SPEC §8 完整工作流（含反问补充）。

**关键点**：
- 加载/创建 `outputs/daily/YYYY/MM/YYYY-MM-DD.md`
- 4 段拆分（做了 / 学到 / 想法 / 卡点）
- **反问机制**（最多 2 轮，不变成问卷）
- wikilinks 自动抽取（识别已有笔记标题）
- 待入库项提示（"→ 调用 quick-kb-capture 单独入库？"）

- **依赖**：WP1
- **验收**：用户口述一句话 → 反问 → 生成结构化日志

### WP6 · 中文模板（4 个）

**交付**：4 个模板，遵循 DESIGN §8.2 设计原则（占位符 `{{var}}`、必填标注、示例内联、模板即文档）。

- **依赖**：WP1
- **验收**：每个模板含 frontmatter + 正文骨架 + 使用说明；占位符可被技能填充

### WP7 · demo-vault 示例

**交付**：`examples/demo-vault/` 含：
- 完整目录骨架（已 init）
- 10-15 条样例笔记（覆盖 concept/resource/idea/daily）
- 1-2 条 inbox 素材（演示 capture → ingest 流程）
- `_readme.md` 说明如何运行

- **依赖**：WP1-WP6 全部完成
- **验收**：用户 clone 后能直观看到 v0.1 的产出形态

                         ├──▶ WP4 (ingest) ◀── 需 WP3 产出测试

- WP4 等 WP3（要有 inbox 输入做测试）
- WP7 最后

## 6. 验收标准（DoD）

- [ ] 空目录运行 `init` → 完整目录骨架
- [ ] `init` 在已初始化目录运行 → 提示而非覆盖
- [ ] URL 输入 → `inbox/clips/` 笔记生成 + `_raw/` 保留原始
- [ ] 文本输入 → `inbox/ideas/` 笔记生成
- [ ] 重复 URL → 触发去重提示
- [ ] inbox 笔记 ingest → 正式笔记（frontmatter 完整、source 链回 inbox）
- [ ] 多观点素材 → 拆为多条原子笔记
- [ ] daily 反问机制有效（≤ 2 轮）
- [ ] 4 个中文模板可用（占位符可填充）
- [ ] demo-vault 可运行
- [ ] 所有技能符合通用规范（幂等 / 可解释 / 降级路径 / 零绝对路径）

---

## 7. 风险与降级

| 风险 | 应对 |
|------|------|
| URL 抓取失败（404 / 付费墙） | 仅基于已得正文生成摘要，标 `partial: true` |
| LLM 抽取观点不稳定 | 提供抽取规则 prompt 模板；用户可手动调整 |
| ingest 字段填充错误 | 标 `status: draft`，让用户确认后转 `active` |
| 模板占位符未填 | 保留 `{{}}`，让用户后续手动补 |

## 8. 测试要点

| 用例 | 期望 |
|------|------|
| init 在空目录 | 完整骨架 + 4 模板 + 标记文件 |
| init 在已初始化目录 | 提示，不覆盖 |
| capture URL（结构化页面） | 干净正文 + frontmatter |
| capture URL（404） | partial 标记 + 错误说明 |
| capture 重复 URL | 去重提示 |
| capture 文本 | inbox/ideas 笔记 |
| ingest 单观点素材 | 1 条正式笔记 |
| ingest 多观点素材 | N 条原子笔记 |
| ingest 字段推断失败 | status: draft |
| daily 空输入 | 进入反问 |
| daily 描述太笼统 | 反问补充 |
| daily 第二轮仍模糊 | 接受当前输入，不强制 |

## 3. 需在实现时澄清的轻微差异

### 3.1 connect 技能的 `related` vs `relations`

**SKILLS_SPEC §4 step 2 表述**：「找出每条笔记的 `related` 字段，自动创建反向 wikilink。」

**DESIGN V2 §6.7 真相**：`relations`（类型化）为主，扁平 `related` 仅作 V1 兼容回退。

**v0.2 实现决策**：connect 技能优先读 `relations.{supports/evolves/supersedes}`，并对未类型化的 `related` 做回退处理（视为弱 `supports`）；写入时只写 `relations`，不再写 `related`。

### 3.2 capture 技能的源类型扩展

dev v0.2 WP9 说「capture 支持完整源类型（PDF/会议/AI 对话/阅读笔记），接 defuddle」。
SKILLS_SPEC §2 输入表已含 6 类源。

**v0.2 实现决策**：保留 v0.1 的 idea/web-clip 两类源 + 新增 pdf/meeting/ai-dialog/reading 四类；PDF/长文通过 defuddle 处理；其余维持 capture 简化原则（最小 frontmatter，分类进对应子目录）。

### 3.3 ingest 的冲突检测

dev v0.2 WP9 说「ingest 加入冲突检测（V2 §SKILLS_SPEC §3 第 3 步）」。
SKILLS_SPEC §3 step 3 要求：相似度 >0.85 提示合并/evolves/supersedes；语义对立时调 memory-agent 判定冲突。

**v0.2 实现决策**：v0.2 没有 memory-agent，冲突检测改由 manager-agent 的 `recommend_relations` 提供候选 + 标题/标签语义对立的简单规则；主动建议加 `contradicts` 关系。v0.3 memory-agent 接入后会替换该降级实现。

### 3.4 `value.reuse` 计算范围

dev v0.2 WP2 说「refresh_value（仅入链数计算 reuse）」。
AGENTS_SPEC §1.3 降级路径说「无查询日志时仅用入链数」。

**v0.2 实现决策**：`value.reuse = 入链数 + Connect 推荐频次（如有）`；查询命中次数依赖 query 技能落日志（v0.2 query 落简易日志），暂不计入。
